# Token Economy
Version: 1

Use this only when choosing how to do a piece of work: which tool, how much to read, how to return it. Best endeavours; make no efficiency claims to the client.

## When to use
- Before fetching, reading, researching or repeating any task.
- Any bot, any job.

## Required inputs and access
- Knowledge of which tools, connectors and scripts are installed on the shared computer.

## Sequence of work
1. The model plans, judges and drafts final communications. Everything else is deterministic where possible.
2. Choose the cheapest reliable method, in this order: a script; a connector or MCP tool; a structured API; text browsing; screenshots last.
3. For research or page extraction, prefer Firecrawl (or another installed extraction tool) over regular web search. Prefer installed tools over the browser.
4. Read only what the job needs. Prefer compact returns (summaries, key fields) over full documents.
5. Load skills and references only when the task needs them.
6. If the same process is done twice, offer to save it as a skill instead of redoing it from scratch.
7. Keep handoffs between bots short.
8. Low-value model work (bulk summarising, formatting) may be offloaded to a cheaper tool where one is installed.

## How to validate
- The method used was the cheapest one that gave a reliable result, and the client-facing output is still complete and correct. Never trade accuracy for savings.

## What to return
- The result, not the working. Mention the method only if the client asks.

## What requires approval
- Installing any new tool, or spending money, including on a paid tier.
- Never silently change the computer's configuration.
